- **Status:** Accepted. Ships in the #145 B2a PR. The merge is gated on the keyed `withheld` smoke leg (D11), not yet run (Jackson, 16/10/2026, Q5). B2b (scope (b'), the reply bound) is optional and owes one keyed re-measure.
- **Date:** 2026-10-20
- **Requirements:** S-5 (SHOULD: hybrid heuristic plus LLM judge, optional, off by default); the design spec `tasks/issue-145-design-spec.md` (signed off by Jackson on 16/10/2026 after two adversarial design reviews); the rulings Q1 (scope (a)), Q2 (default off, flip rule fixed), Q3 (no reply bound now), Q4 (no skills-at-load) and Q5 (the keyed smoke leg blocks the merge).

## Context

Since 2026-09-08 a flagged tool result has been annotated for the model with a plain note and never withheld (ADR-0026, ADR-0035, ADR-0037). The security model names that its most important honest statement (R-4): the note cannot say what to ignore, and a payload that evades the lexical scanner is shown with a note beside it. ADR-0037 wired the judge into the session and deferred the decision to withhold to B2 (#145), to be made from the live `judge-call` rows rather than the corpus alone. ADR-0038 and #152 made those rows readable: a provider refusal is a distinct `refused` state, and no live row falls inside the ambiguity window between the two merges.

## Decision

**D1. The model's copy is replaced through `updatedToolOutput`, shape-preserving, with one placeholder per non-empty string leaf, except the CLI's shape leaves, plus a withhold notice.** `updatedToolOutput` is the field the SDK declares for replacing the output of any tool (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:2182`; `updatedMCPToolOutput`, `:2186`, is MCP-only and the SDK says to prefer `updatedToolOutput`); `decision: 'block'` returns the raw result with the reason appended (ADR-0035 spike p9), `continue: false` (`sdk.d.ts:6484`) would end the turn on one flagged read, and a plain-string or partial-object replacement is dropped silently (spike p2, p3), which is why the walk, not a string, is the replacement. `applyWithhold` (`src/session/session.ts:1121`) walks the copy the judge judged (the redaction rewrite when one applied, else the raw response) with `rewriteStringLeaves` (`src/session/rewrite-leaves.ts:32`) and a leaf function that keeps `isShapeLeaf` leaves (below), so numbers, booleans, null, keys and order pass through and empty leaves stay empty. Every other non-empty leaf becomes `withholdPlaceholder(tool)` (`src/session/withhold.ts:25`), a fixed sentence carrying the marker `[WITHHELD:judge-block]` and the cleaned, bounded tool name only: no rule id, no excerpt and no attacker byte. The `additionalContext` note is `withholdNotice` (`src/session/withhold.ts:37`), because today's note says the result is "shown to you unchanged". Zero leaves replaced is NOT a withhold: the walk ran and found nothing it could replace (every string leaf empty or kept as a shape leaf, or the payload only in object keys), so nothing is returned on the rewrite channel, the result gets today's note and `withholdUnrewrittenWarning`, and a `tool-rewrite` row `kind: 'withhold', outcome: 'unrewritten'` is written (`src/session/session.ts:1151-1152`). A walk that could not run (non-JSON, past `MAX_REWRITE_NODES` or `MAX_REWRITE_DEPTH`, `src/session/rewrite-leaves.ts:14-15`, or a throwing proxy) is `skipped`, with its own warning and row (`src/session/session.ts:1146-1147`). The walk is by reference over the object the judge judged. A withheld result's primary channel is verifiable in band: the placeholder lands in the `user` `tool_result` the verifier already reads (D4), where the note stays the unobservable channel it is today.

*Note, 20/10/2026 (live FAIL of the keyed `withheld` smoke leg; issue #203, Task 8b).* The first live run FAILED: `tasks/issue-145-evidence/prb2-smoke/withheld.json` records `status: FAIL` (the SDK dropped the withhold), a judge block of `state: judged`, `judge: block`, `composed: block` with `withholdDecided: true`, a `withhold` row with `outcome: leaked`, and a `userResult` with `containsSynth: false`, `containsMarker: false` and `containsFixtureLine: true`, so the raw file reached the stream. Root cause: CLI 2.1.201 safeParses a built-in tool's `updatedToolOutput` against that tool's output schema and silently reverts to the ORIGINAL output on mismatch (MCP tools are exempt; see the 20/10/2026 note under ADR-0035 D1). The first version of `applyWithhold` replaced every non-empty string leaf, including Read's discriminator `type: "text"`, so the rewrite failed the schema and was discarded. The keeper rule from #203 (`isShapeLeaf` in `src/session/rewrite-leaves.ts`, ADR-0035's #203 note) now applies to the withhold: a leaf is kept unchanged only when the tool is not an `mcp__` tool, the leaf's key is one the pinned SDK declares as a string-literal field, and the value is exactly a literal declared for that key. The withhold therefore replaces every non-empty string leaf EXCEPT a CLI-declared literal on a built-in tool. A kept leaf is CLI vocabulary, not content: it adds no span line and is not counted as replaced, so a response whose only non-empty leaves are kept is `unrewritten`. Residual, as in ADR-0035: a built-in tool whose constrained string fields `sdk-tools.d.ts` does not declare still reverts; the stream verifier then reads `leaked` or `unobserved`, so it is detected, not prevented. A withheld Read of an image keeps `type: "image/png"` and replaces `base64` with the placeholder, which the API will reject: it fails closed (an API error, not a leak). The Status line at the top of this ADR stays pending until Jackson re-runs the leg (Task 9).

**D2. Scope (a): withhold only when the composed verdict is `block` AND the judge's own recorded verdict is `block`.** The predicate is `decidesWithhold` (`src/session/judged-scan.ts:243`): state `judged`, composed `block`, and the record's `ok` verdict `block`. It never fires on `ask` (ADR-0026 decision 3: medium-confidence, far too broad; on the shipped model (sonnet) the only measured judge false-flags were `ask`, and haiku made judge-caused false-blocks, ADR-0038), and never on a heuristic-only block, because the judge is not consulted on one (`src/security/injection/judge.ts:319`). Scope (b), withholding every composed `block`, was rejected: the high-confidence rules block a README with a badge query string, a quoted chat template and a document that describes injection (ADR-0026's accounting), and the zero-false-block gate is on a corpus curated to avoid those shapes. Scope (b') (escalate a heuristic `block` to the judge and withhold when it concurs) would close the trigger-phrase bypass, but its false-block rate on benign heuristic-blocked text is unmeasured, so it waits for a `--escalate-blocks` redteam arm and benign heuristic-block holdout cases read through the five-sample gate (B2b). The strongest argument against (a) is that the rule table is public, so an attacker appends a trigger phrase and is shown with a note; it stands because that is never worse than today. The padding bypass (D6, item 1) is different: it is permanent. Closing it needs chunked judging, a new judge population for B2b at the earliest, or withholding on `oversized` itself, which withholds every legitimate large result on no evidence. Padding is loud, not silent (the row reads `state: 'oversized'`, `composed: 'ask'`, `withholdDecided: false`), and batch 3 counts those rows.

**D3. The setting: `judge.withhold: "off" | "block"`, default `off`, user layer only, `"ask"` refused; the seam carries `withhold?: 'block'`.** `JUDGE_KEYS` gains `withhold` (`src/security/injection/judge-settings.ts:35`); `parseJudgeSettings` refuses `"ask"` with a message naming ADR-0026 decision 3 (`:67-72`), rejects any other value (`:74-76`) and refuses `"block"` with `mode: "off"` (`:77-79`), never echoing the value. `runJudgeDeps` passes a third key `withhold: 'block'` only when set (`src/cli/run-judge.ts:19`), `SessionJudge` gains `withhold?: 'block'` (`src/session/types.ts:546`), validated in `validateSessionJudge` (`src/session/judged-scan-validate.ts:27-29`), and the start line gains `, withhold: block` (`src/cli/run-judge.ts:26`). The project layer's `judge` key stays unparsed with the existing warning, so a cloned repository can neither switch withholding on nor off. It is a tightening lever in the user layer, like `judge.mode`. Off is today's path: `session.ts` reads `withholdOn` from the seam (`src/session/session.ts:675`) and takes no withhold branch without it.

**D4. The verifier is re-owned for a withhold.** `PendingRewrite` gains `kind: 'redact' | 'withhold'`. When the predicate fires after the judge, `applyWithhold` replaces the redaction entry in place (a new object, not a mutation) or enrols a fresh one: `kind` is `withhold`, `markers` is `[WITHHELD_MARKER]`, `spanLines` KEEPS the secret span lines (a secret surviving a withhold is still a leak) and gains the content first lines capped at `WITHHOLD_SPAN_LINES_MAX` (32), and `failedClosed` is false (`src/session/session.ts:1237-1257`). `decideRewriteOutcome` is unchanged: a marker and no span is `applied`, a span is `leaked`, else `unobserved` with its reason. The span oracle is the first non-empty line of at least `MIN_SPAN_LINE` (8) characters of each leaf, with any line the placeholder or marker contains excluded (`withholdSpanLine`, `src/session/withhold.ts:55`), so a blank first line cannot make a dropped withhold read `unobserved` and an applied withhold cannot read `both-present`. A `leaked` withhold warns with `withholdLeakedWarning` (`src/session/judged-scan-lines.ts:63`), or the hook-timeout line when the hook was cancelled (`src/session/session.ts:1285-1289`). Attacker text in `spanLines` is per-run memory only, never persisted, logged or thrown (G-5, G-11). Three honest losses: (S8) a leaf that failed redaction closed carries the sentinel; the withhold replaces it too, so the `tool-rewrite` row reads `applied, kind: 'withhold'` where redaction alone would read `failed-closed` (the pass-2 warning still fires); (S6) on the `unrewritten` and skipped paths pass 2 has already written its row, so a withheld call carries TWO `tool-rewrite` rows for one `tool_use_id`, and the join selects `kind = 'withhold'`; (S7) the hook's abort listener is removed at `dispose()`, so an SDK-side abort after that and before the SDK's own timer gets the generic leaked line rather than the hook-timeout line. Re-owning rather than dropping the entry matters because a dropped withhold means the model received the raw copy, the worst outcome of the path, and it must be the most visible.

**D5. Two row keys, `OutputRewrite.kind` required, decisions and landings counted apart, no migration.** `JudgeCallPayload` gains `withholdDecided?: boolean` (`src/telemetry/types.ts:200`), a DECISION: the harness decided to withhold and returned the rewrite; whether it landed is the `tool-rewrite` row's claim. It is optional only because the validator also runs on the read path for rows written before B2a, and `JUDGE_CALL_KEYS` gains the key so the closed set holds (`src/telemetry/store.ts:164`, validator `:383`). `ToolRewritePayload` gains `kind?: 'redact' | 'withhold'` under the same read-compatibility rule (`src/telemetry/types.ts:101`, mirror `src/telemetry/store.ts:102`), and `OutputRewrite.kind` is REQUIRED (`src/session/types.ts:520`), the one non-additive effect: a consumer who builds an `OutputRewrite` adds it. `JudgeSummary.withholdsDecided` counts decisions from the entries (`src/session/judged-scan-fold.ts:35`); the `[harness] judge:` line prints `withhold(s) decided` (`src/cli/run-judge.ts:48`) and the `[harness] model-facing:` line prints `withhold(s) applied` from `outputRewrites` with `kind === 'withhold'` and `outcome === 'applied'` (`src/cli.ts:620-632`), while its `rewrite(s) applied` count excludes the withhold kind (`:619`). O-2 (the security lens of PR-B1) is answered by the join on `tool_use_id`: `withholdDecided = true` against `outcome = 'leaked'` or `'unobserved'` on the `kind = 'withhold'` row is the query for "the harness decided to withhold and the model may have the raw bytes". No SQL migration: the CHECK constrains `type`, not the payload (#152 D8).

**D6. Every degraded judge state fails open to today's note; nothing is withheld on the floor alone.** The predicate requires `state === 'judged'`, so `cap-reached`, `stopped`, `queue-timed-out`, `timed-out`, `failed`, `refused`, `oversized`, `hook-cancelled` and `not-escalated` leave ADR-0037's behaviour untouched, and the withhold runs after the step-6 re-decide so a hook cancelled during the custom hook never withholds (`src/session/session.ts:1497-1502`). Six content-controlled ways to be shown rather than withheld, as the spec numbers them: (1) padding past `MAX_JUDGE_INPUT_BYTES` (131 072, `src/security/injection/judge.ts:17`, checked at `:324`), deterministic, no model call, PERMANENT under this design and surviving B2b; (2) the trigger phrase, a heuristic `block` the judge is never asked about (`src/security/injection/judge.ts:319`), closed by B2b's (b'); (3) a provoked provider refusal (`refused`, composed `ask`), provider-controlled and permanent; (4) a provoked unparseable reply (`failed`, `errorKind: 'unparseable'`, `src/session/judge.ts:143`), probabilistic, narrowed by B2b's bound; (5) the content-provoked early stop after `JUDGE_EARLY_STOP_AFTER` (3, `src/session/judged-scan-constants.ts:14`) and the four-slot-holders-plus-a-chosen-fifth route to `queue-timed-out`, the long-reply route closed by B2b; (6) cap exhaustion, where a repository that makes the agent read many files before the payload lands exhausts `maxCallsPerRun`. B2b narrows this set (closes 2, closes the long-reply route of 5, narrows 4) and cannot close 1, 3 or 6. Each bypass leaves the model in today's state (the note), not a worse one, and each is surfaced by the row's state and `withholdDecided: false` and by the early-stop, slots-held and cap warning lines (`src/session/judged-scan-lines.ts:19-33`).

**D7. The failure hook annotates only.** `PostToolUseFailureHookSpecificOutput` declares `additionalContext` and no rewrite (`sdk.d.ts:2159`), and the model has already received `error`, so a judge `block` on a failed call produces the note with `judge-block` and `withholdDecided: false` (`src/session/session.ts:1587`). An attacker who controls a tool's exit code selects this path (R-22). UNCHECKED (U4): whether a failed Bash call's `error` carries the command's stdout as well as its stderr; the smoke's `failure-stdout` leg answers it and records only.

**D8. Skills-at-load escalation: NO, with a measurement precondition.** The skill loop keeps the synchronous heuristic. There is no live data (every `judge-call` row is `post-tool`), the judge's `block` criterion ("instructs, pressures or manipulates the reader to act against its operator", `src/session/judge.ts:56-58`) describes a skill by design so the zero-false-block measurement on tool-output-shaped text does not transfer, a judge `block` on a skill drops it with no override (ADR-0026 D8), and the operator chose the directory. It returns only after a skill-shaped holdout slice (benign instruction-shaped skills and malicious ones) passes the five-sample gate with the zero-false-block rule, or ADR-0026 R1 fires. For whoever does it, two plumbing constraints (ADR-0037's second extension point): `judgeRun`, `harnessSessionId` and `turnId` must move above the skill loop together, or the `writeRow` closure reads the ids in their temporal dead zone; and `JudgeCallPayload.phase` must not widen `ToolTracePhase` (shared with `tool-trace` rows), so a judge-specific mirror `JudgeCallPhase = ToolTracePhase | 'skill-load'` needs its own presence record, drift test and validator set. Neither move is made here.

**D9. No reply-length bound in B2a; decision 16 stands as record-only.** The pinned SDK 0.3.201 has no typed output-token cap on `Options`; `maxOutputTokens` is a field of `ModelUsage` (`sdk.d.ts:1237`), a report, not a control. The candidates are (i) `CLAUDE_CODE_MAX_OUTPUT_TOKENS` through `Options.env` (`sdk.d.ts:1407`), a provider-side bound, (ii) `includePartialMessages` with a client-side abort once cumulative text passes a byte bound, (iii) `thinking: { type: 'disabled' }` and `effort: 'low'`, which bound thinking and not the reply, and (iv) no bound; (iv) now, then (i) in B2b together with (b'). The trap for B2b: a reply cut by the bound surfaces as the assistant-message error `'max_output_tokens'` (`sdk.d.ts:2798`); if the result then carries an error subtype it reads `call-failed`, which counts toward R6, so three cut replies before anything is answered would trip the early stop the bound exists to remove. A cut reply must map to a neutral kind (`reply-too-long`) explicitly. UNCHECKED (U1): whether the bundled CLI honours the variable for a `-p` child. Every candidate is a query-key change that owes a keyed five-sample re-measure (ADR-0036 D8), which B2b pays once for both items. While padding and the trigger phrase are open the bound closes nothing an attacker needs.

**D10. Ship off; Jackson sets `"withhold": "block"` in his own `~/.harness/settings.json` for batch 3; the default flips by a rule fixed before batch 3.** The rows justify building the mechanism and do not justify defaulting it on (0 flagged rows, so 0 observations of a withhold); defaulting on now would be a corpus-only decision. The pre-registered flip rule, as the spec (`tasks/issue-145-design-spec.md`, D10) states it: the default becomes `block` when the judge is on if, over batch 3 read from an operator-owned DB only, (1) there are at least 150 judged rows on benign traffic across at least three repositories and at least six tools, with 0 withholds (bound 2.0%) and at most 150 x 10% flags of any kind; (2) a seeded-hostile scratch clone (the three corpus semantic misses and the twelve holdout malicious cases planted as files, read by the agent; clone discarded after) shows every withhold `applied` with `kind: 'withhold'`, 0 `leaked`, and `unobserved` only with reason `no-user-message` at stream end; (3) the keyed withhold smoke leg PASS; (4) a PIN, not a measurement: no row with `withholdDecided: true` whose `heuristic` is `block`. If (1) fails on a false withhold the default stays off and the row's tool and rule ids go into the revisit list below; if (2) shows a `leaked` withhold, B2a reverts to annotate-only for that shape before any default change. The cost the rule accepts: 0 of 150 bounds the benign false-withhold rate at 2.0% per judged result (95%), so a 50-call session may carry one false withhold in expectation at the bound, and two or more about a quarter of the time; each is a lost tool result for the run. Batch 3 also counts `oversized` rows, so the padding floor is measured on real traffic.

**D11. One PR now (B2a) with a keyed smoke leg; an optional later PR (B2b); no PR for D8.** B2a is downstream of the judge's verdict and testable keylessly: no prompt, model literal, parser or query key changes, so no re-measure is owed. `scripts/smoke-judge-session.mjs` gains a `withheld` leg (a Read of a fixture that is one of the three corpus semantic misses, each `judged` with judge `block` and heuristic `pass` in all five #148 samples; oracle: the `user` `tool_result` carries the placeholder and no fixture line, the `tool-rewrite` row reads `kind: withhold, outcome: applied`), a merge blocker, and a `failure-stdout` leg that records only. B2b is scope (b') plus the reply bound, measured together with the `--escalate-blocks` arm and the benign heuristic-block holdout cases.

**D12. A new ADR, not an amendment.** B2 changes policy (what the model receives), which ADR-0035 reserved for the judge and ADR-0037 deferred to B2; #152 amended ADR-0038 because it changed representation only. The dated-note pattern still applies to the ADRs whose sentences become false (0011, 0026, 0035, 0037).

## Consequences

**Positive**

- The model-facing withhold exists and lands verifiably: the placeholder is read back in band by the re-owned verifier entry.
- With `judge.withhold` absent the behaviour is ADR-0037's (the seam carries no key and `session.ts` takes no withhold branch), and the project layer cannot switch it on.
- No judge measurement is invalidated: the prompt, model literal, parser and query keys are untouched.

**Negative, accepted**

- A false withhold costs a task (D1's own argument: a retry is judged again by a non-deterministic judge), and the rows are the only evidence it happened. The live false-flag bound is 4.1% per judged result, and the flip rule accepts 2.0%.
- The six content-controlled fail-opens of D6, two of them permanent and one deterministic and free (padding).
- Key-only and skipped residuals: a payload that sits only in object keys or in empty leaves is withhold-proof (`unrewritten`), as is output the walk cannot run on (`skipped`). The `withheld` smoke leg drives Read, whose text sits in a string leaf; an MCP tool can return a key-only payload or an over-bound one (unverified live).
- `withholdDecided` is a decision. A SQL reader must join it to the `kind = 'withhold'` `tool-rewrite` row to read it as a landing, and a withheld call on the `unrewritten` or skipped path carries two `tool-rewrite` rows for one `tool_use_id`.
- The `failed-closed` row reads `applied` when a withhold replaced the sentinel (S8), and `OutputRewrite.kind` is non-additive for any consumer that builds one.
- **A withheld result's text still reaches the operator's local telemetry store.** The `tool-trace` row's `resultSummary` is the pass-1 secret-redacted output (`src/session/session.ts:1442-1453`, #84 D1), written from `telemetryText`, which `applyWithhold` never touches. Withholding governs what the MODEL receives, not what the local store retains.
- **A residual that under-claims.** The redaction pass records, for a leaf that failed closed, the ORIGINAL leaf's first line as a span (`recordFailedSpan`, `src/session/session.ts:1101-1104`, only when that line is at least `MIN_SPAN_LINE` (8) characters), and `applyWithhold` keeps those spans (`keptSpans`, `:1243`, `:1252`). Exactly one `updatedToolOutput` is returned (`const outgoing = withheld ?? rewrite`, `:1513`), so an SDK-dropped withhold delivers the raw `tool_response`, never the sentinel copy, and `leaked` is then correct. But when a failed-closed leaf's first line is under 8 characters, no raw span is recorded for it, the only span the withhold adds is the sentinel line (which can never match what the model receives), and a dropped withhold of that leaf reads `unobserved` (`neither-token`, `:1319`): an under-claim, the same as the redaction-only path today.
- **Only the withhold rewrite is guaranteed a notice.** The withhold branch requires `decision.deliver` (`src/session/session.ts:1501`), so a withhold always carries the withhold note; a pass-verdict redaction rewrite carries none, by #84's design (`src/session/session.ts:1510-1530` returns `updatedToolOutput` alone when the notice is null).
- The smoke drives Read only, so MCP tools' withhold is unverified live; the padding floor is measured on batch 3, not closed.

## Alternatives considered

- **Withhold every composed `block` (scope (b)).** Rejected: it blinds an agent to a badge README and to this repository's own threat-model document (D2).
- **Withhold on `oversized` or `refused`.** Rejected: no evidence, and legitimate large results (a build log, a long Read) would be withheld along with the padded ones.
- **`decision: 'block'` or `continue: false` as the channel.** Rejected: the first returns the raw result with the reason appended (ADR-0035 spike p9), the second ends the turn (`sdk.d.ts:6484`).
- **Drop the pending verifier entry.** Rejected: a silently dropped withhold is the path's worst outcome and would be invisible.
- **Default on.** Rejected: it would be a decision from the corpus alone, with 0 observed withholds.

## UNCHECKED, carried

- U1: the bundled CLI honours `CLAUDE_CODE_MAX_OUTPUT_TOKENS` for a `-p` child.
- U2: live `stream_event` emission (the partial-message candidate).
- U4: stdout on a failed Bash `error`; the `failure-stdout` leg answers it.
- Billing of an aborted request.
- The CLI's default callback-hook timeout (moot while a judge is on: the matcher timeout is set explicitly).
- #140's merge order, and the order in which an ambient hook's `updatedToolOutput` merges with this one.
- Whether the current SDK accepts a Read rewrite whose `type: 'text'` leaf became the placeholder: ADR-0035's spike p7 is older-SDK evidence, and the `withheld` leg is what answers it.

- A skill-shaped holdout slice passes the gate (ADR-0026 R2).
- The SDK signals a dropped rewrite in band (ADR-0035's revisit).
